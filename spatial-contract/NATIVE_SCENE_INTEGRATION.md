# Spatial P0 W2: actual source → Go frame plan → pinned native spatial PCM

DLE: [Spatial integration #27](https://github.com/SemperSupra/stable-character-pipeline/issues/27), parent [Spatial #18](https://github.com/SemperSupra/stable-character-pipeline/issues/18). **This is a stacked DRAFT** on [W1 PR #35](https://github.com/SemperSupra/stable-character-pipeline/pull/35), which is stacked on [contract PR #22](https://github.com/SemperSupra/stable-character-pipeline/pull/22). No branch has been merged or released.

**Actual upstream usage:** public Ubuntu GHA fetches VideoLAN `libspatialaudio` **exact SHA `d149ed9744fd399b835c6f2920511f8cbcfce5ea`**, checks LGPL source, Meson builds it with built-in MIT test HRTF, runs native tests, and builds our small original C++ adapter dynamically against its documented headers. We do not substitute a custom panner.

**Source fidelity:** generate original 410Hz/48k/1-second PCM16 mono with a real SHA256 and `spatial_audio.v1` public scene. Native plan command checks full file and rights/source hash and emits 47 sample-contiguous 1024-frame blocks (last block 896) with listener-relative ENU azimuth, elevation and distance at each block's **start** sample. The adapter reads the REAL PCM audio samples and each Go pose, runs VideoLAN `Renderer::AddObject` and `GetRenderedAudio` and crops padding on the last block, to exactly 48000 samples/channel. Supported first two native targets: 5.1 channel order FL,FR,FC,LFE,SL,SR; headphone binaural from built-in admitted MIT test HRTF. Native stereo is **quarantined due to proven NaN**, so stereo is a distinct two-channel postrender conversion from 5.1, using recorded coefficients and explicitly omitting LFE. Derived stereo ≠ licensed Dolby/THX output or actual 2.1 bass management.

**Verification:** independent Go runner invokes FFprobe and full FFmpeg float32 decode of real outputs, checks 48000 frames, PCM sample rate, channels, finite sample values, absence of silent/clipped waveform and source/destination hashes. The workflow additionally changes canonical emitter X-position, creates a different Go block plan from the *same admitted source*, rerenders 5.1 and requires a different PCM output checksum. Go stdlib tests and race/vet run on every PR.

**Explicit limitations:** poses update at block boundaries, not native sample-by-sample acoustic interpolation within blocks. Only one monophonic emitter, original synthetic source type and two native targets in W2; no dynamic head tracking, arbitrary HRTF, directivity, room acoustics, Doppler, physics distance response, cross-platform 2.1 bass management, multiple sources, true pitch/roll or immersive certification. This is numeric/custody smoke qualification, not a human headphone localization acceptance or user-confirmed iPhone file. Upstream library internal HRTF for this test does not entitle reuse of other nonfree impulse responses. Separate creator-facing sound-stage UI, native Ardour project and real playable delivery remain open.

**Human/automation/agent interfaces:** creator can edit canonical JSON emitter movement and actual original WAV source, with stable IDs and reliable sample count. Operator uses `spatial-admit` then `spatial-blockplan` then the native engine and `nativeverify` in bounded reproducible public GHA; agent uses versioned schema, stable JSON receipts and explicit unsupported capabilities. Future full UI required for actual human editing experience.

**No merge, release, deploy, private final character assets, private/paid CI minutes, or publication of generated audio.** On failure record exact CI reason and next DLE baton instead of reducing tests.
