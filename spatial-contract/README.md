# spatial_audio.v1 contract: source-independent spatial sound scene

This is a **strict, machine-readable admission and planning contract**, not yet an acoustic engine. It complements the separately tested `scene_audio.v1` timeline and Csound music/FX stem generation; true bidirectional integration is not yet implemented. Authority: [Spatial Audio DLE #18](https://github.com/SemperSupra/stable-character-pipeline/issues/18).

**Canonical world coordinate frame**: meters, right-handed ENU (X East/right, Y North/front, Z Up), positive yaw toward X/right from North/front. Source and listener trajectories are strictly ordered in integer milliseconds, and initial positions are required at t=0. Any future renderer must explicitly convert this world frame into its native azimuth/elevation and report the conversion. Never silently equate degrees, radians or opposite handedness.

**Output target separation:** the same emitter and listener metadata can request 2.0 stereo; headphone binaural HRTF; stereo with 2.1 bass management; discrete 5.1, 7.1, 5.1.4, and 7.1.4. Each profile lists canonical *desired output channel labels/order*. Renderers are responsible for translating their native channel layout into these labels. Merely obtaining eight channels does **not** verify an actual 7.1 channel mapping. A stereo 2.1 delivery has two PCM channels and `lfe_policy=bass_managed`, **not a fabricated third discrete LFE**. Every binaural render must have a rights-admitted HRTF provenance token. In this smoke fixture `builtin_mit_test` refers to upstream libspatialaudio’s built-in HRTF test dependency and is not a portable SOFA file.

**Privacy/rights:** no human identity audio is emitted or uploaded from public CI; any `PRIVATE_FINAL_CHARACTER_VOICE` scene is rejected by public planners. No private model weights, selected voicepacks, reference recordings or proprietary Dolby/THX codecs or trademarks enter this branch.

**Three audience contract:** human creators can retain the same scene/object IDs and edits in a future visual sound-stage/timeline; operators can run `go run ./cmd/spatial-plan fixture > scene.json` then `go run ./cmd/spatial-plan plan scene.json` and verify JSON reports; developer/agent actors can use the typed Go schema, strict JSON deserialization, stable frame convention and event/order invariants. Native Ardour UI and spatial browser manipulation are not claimed until tested.

The public workflow exercises Go stdlib with race, strict source privacy, channel-order and LFE policy red tests plus a synthetic seven-profile planning receipt. Its outputs are metadata-only and every requested profile says `UNQUALIFIED_UNTIL_BACKEND_PASS`. The corresponding real sound-renderer workcell is separate [spatial PR #21](https://github.com/SemperSupra/stable-character-pipeline/pull/21), which must show finite non-silent audio and channel mapping before promotion. A SHA256 scene receipt is an integrity identifier, not evidence of spatial perceptual correctness.

Do not merge, release, deploy or promote final human character assets.
