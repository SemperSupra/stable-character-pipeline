# R036: actual BodyParts3D v4.0 element/OBJ custody, not anatomy acceptance

This is an independent public source-safe probe stacked on #569's already-pinned BodyParts3D 4.0 lexical coverage. The live official LSDB source states an essential distinction: **only atomic ELEMENT components are stored as polygon OBJ files; COMPOUND FMA organ concepts are lists of FJ element file IDs**. Therefore the 2,905 IS-A / 1,368 PART-OF FMA semantic records and even the 52 coverage labels cannot be treated as distinct actual downloadable meshes. Source authority: https://dbarchive.biosciencedbc.jp/data/bodyparts3d/LATEST/README_e.html ; data 4.0 as of 2013-06-19, licensing page updated 2025-02-27, CC BY 4.0 with exact required DBCLS attribution.

This probe reads exactly:
- `partof_element_parts.txt` (3-column official TSV: concept id, name, element file id) and records SHA256.
- `partof_BP3D_4.0_obj_99.zip` (~62MB compressed, official PART-OF 99%-decimated mesh archive), download to **ephemeral GitHub public free-tier CPU only**, never commit/republish assets. Uses at most 80MB compressed, cap 10k ZIP entries and read **up to 12 actual FJ OBJ component meshes**, max 6MiB each, never write extracted geometry to disk.
- Tested source concepts: heart FMA7088, left lung FMA7310, right lung FMA7309, skin FMA7163, femur FMA9611, diaphragm FMA13295, liver FMA7197; some may be COMPOUND, lack a PART-OF element, or be missing a mesh. Every absence is recorded as UNKNOWN/HOLD, not false anatomical absence. Source geometry checks validate actual OBJ vertex/face counts, indices, finite bounds and sha hashes. This **does not prove closed manifold/medically correct fit, anatomical sex variant, reference unit, detailed tissue/skin fidelity, or physical simulation**.

The first real run discovers the exact source text ZIP SHA and member layout, then those digests must be **hard-pinned on a second run**, as with other R036 donor admissions. This source-only code contains no private named-human character, scripts have strict stderr/exit failures and checkout pin, and workflow avoids private GHA Actions. Running a 62MB public CPU archive download has greater free-tier bandwidth/time cost than the earlier four small metadata TSVs, so this is bounded to one official PART-OF archive. No medium/large asset binary is published in PRs/artifacts. Release merge/deploy/HIL gates remain unchanged.

The likely corrective after this is a FMA→FJ component graph, then per-element source SHA/geometry availability and correspondence before composing anatomical organs. Do not use FJ component identity as BP representation identity or FMA concept identity.
