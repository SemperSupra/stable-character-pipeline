# R64 real small VLM blind structural critic on R63 inverse scene outputs

**Authority:** [Oneirifact R63 critic #88](https://github.com/SemperSupra/oneirifact-private/issues/88#issuecomment-6899606776), source-safe synthetic inverse fit [R63 public PR #514](https://github.com/SemperSupra/stable-character-pipeline/pull/514), existing [public R033 SmolVLM CPU validation](https://github.com/SemperSupra/stable-character-pipeline/actions/runs/43745064137). This is a new **real pretrained vision-language inference** workcell on exactly the inverse-scene candidate renders, **not** learned 3D reconstruction or native Oneirifact integration.

**R0 insight:** The program-search C source-graph result selected sofa/chair armrest programs **(2,0)** for source scene0 although true is **(2,2)**; another case recovered **(2,2)**. Its heldout *visual IoU* improved despite the latent/semantic wrong chair structure. This is a known scientific negative even if the visual VLM does not detect it. Candidate D always has correct armrest type by construction but continuous dimensions may differ, so reference-vs-candidate visual inspection still needed. **Important:** a physical graph mismatch might not be visible from an occluded camera; an honest critic may answer UNKNOWN, not simply DIFFERENT.

**Experimental design, preregistered before outputs:**
- Source-controlled original 48×48 visual observations of three stylized objects with four known perspective cameras; real source mesh and armrest counts are kept out of VLM text input.
- Compare in two unseen camera views (2 and 3), two source cases, two R0 candidates: discrete-program C and RGB-D initial-fit D = **8 reference/candidate 512×286 RGB panels**, plus **one exact-pixel-identity pair** as a VLM calibration/negative control = **9 forward passes**.
- Prompt explicitly focuses on **BLUE chair armrest structure**, answer exactly `MATCH | DIFFERENT | UNKNOWN`, abstain if occluded. No source truth label, optimizer score, source arm configuration, latent parameters or machine receipt passed in prompt/image. Panels show left REFERENCE/right CANDIDATE and are never made from user/real-person media.
- Actual pinned original R033 model candidate `HuggingFaceTB/SmolVLM-256M-Instruct@d039ab0d4b9311b617e8ffec1d06c8464364aeb3`, upstream safetensors, `transformers==4.57.1`, `torch==2.6.0` CPU wheel, no token or paid/remote inference service; wheel install and HF checkpoint downloaded on standard **free public** Ubuntu runner. 17-minute job ceiling, 3-day retention.
- Record SHA256 of each input panel, prompt, model revision, raw/normalized model response, per-sample CPU inference seconds, RGB pixel difference, source structural armrest relation, VLM UNKNOWN/parseability and disagreement, process peak RSS. DO NOT interpret a single 9-case figure as calibrated accuracy; graph structural relationship and image observability differ.

**Priority falsifier:** `exact_pixel_identity_control` must be treated as a perfect visible MATCH from the same pixel observations. However non-perfect VLM output is a **scientific RED**, not a code bug necessarily; do not force pass or select prompt after outcomes. Conversely if both panels share the same silhouette while armrest graph differs, VLM MATCH does not prove actual 3D semantic recovery and demonstrates need for geometric/graph oracle. The evaluator should not automatically promote `REVIEW_READY` based on model agreement. Any model output is an uncertain observation with provenance.

**Stop conditions:** no VLM access token, private image content, Oneirifact private code, production release G5, new model training/promotion, anthropometric or licensed human claims, external media. Existing live critic interfaces in Oneirifact `internal/demoflywheel` remain product authority and are not duplicated in this public experiment. If CPU memory/time fails, preserve RED with exact log and do not buy paid or private minutes.

**Expected practical lesson:** Determine whether a tiny actual visual model can flag wrong procedural furniture structure from low-resolution rendered views, and when it abstains/fails. Compare that to exact source graph/geometry checks, not claim the critic creates an editable mesh.
