# R63 — original-object inverse graphics bakeoff (free public CPU R0)

**Research owner:** [Oneirifact critic flywheel #88](https://github.com/SemperSupra/oneirifact-private/issues/88#issuecomment-6899176131), geometry-adapter evaluation [#7](https://github.com/SemperSupra/oneirifact-private/issues/7#issuecomment-6899176540). This is **independently authored synthetic mathematical R&D in a public repository**, **not a copy of private Oneirifact source**, a product merge, or an imported pretrained model. The project remains on its separate v0.0.1 preview release track. Supports human-readable DLE, machine receipts, and agent-replay source.

## Question and restrictions

Does object identity segmentation improve inverse modeling given equal object-family parameters and matched numerical fitting budget? What is gained/lost by discrete part-program search versus RGB-D geometric initialization? What happens when source instance masks are noisy? Fit a simple living-room scene with a sofa, armchair and stylized stationary mannequin using *actual* 3D calibrated camera ray tracing and numerical parameter adjustment. The objects are analytic **part-grouped boxes and a head sphere**; this is not a human mesh/rig, learned Gaussian splat, textured furniture benchmark, actual SAM, Mira, PGN, native Oneirifact source, VLM or GPU experiment.

**Controlled latent parameters:** each object has `(x_m,y_m,scale_x,scale_y,scale_z)`; 15 continuously fitted parameters across three objects. Canonical source has two sofa arms and two chair arms; C must also recover two 0-or-2 armrest configuration variables (discrete graph). No arbitrary rotation/mesh topology/UV/body rig. Two source scenes with fixed intentional source-offset errors, four **perspective** pinhole cameras at known world poses, 48×48 RGB/depth/instance label renders, with views 0/1 as fitting data and views 2/3 **held out**. Per-pixel metric positive optical-axis depth generated by exact ray–box/ray–sphere intersection (no source geometry passed directly to fitters). Includes genuine depth/occlusion and distinct part silhouettes; constant authored synthetic material colors are not learned textures. Original self-tests reject nonfinite/invalid camera or negative dimensions, check source self-reprojection and output hashes.

## Actual treatment protocols

| Treatment | Fit observations | Model | Budget/fairness |
|---|---|---|---|
| A — whole scene | Global foreground silhouette and metric Z-depth, **no instance IDs** | Same three object types and 15 continuous variables as B | 4 coarse-to-fine step levels × 15 vars × ±2 + initial = **121** objectives, 242 paired perspective renders per case |
| B — object first | Oracle per-object instance silhouettes and metric Z-depth | **Exactly same model/continuous variables/start/eval budget** as A, optimize joint scene masks/occlusion | 121 objectives, 242 renders |
| C — procedural parts | Instance masks/depth, two **unknown discrete armrest rules** | First fit arm-free source, search four discrete structure proposals, then continuous refit after discrete selection | **More compute than A/B**, therefore separate *capability*, not compute-equal victory |
| D — geometric hybrid | Instance labels + calibrated metric depth unprojection for a visible-surface initializer, then object fit | Same 15 variables as B and same 121 optimization objectives after initializer | Source depth initialization extra computational advantage; never call it a matched observation baseline |
| E — noisy-mask control | B's observations with deterministic removal of ~8% of labeled **training** pixels | Same 15 variables, same init as B, full source geometry held out | 121 objectives, 242 renders |

These are **methodological analogues**, not literal executions of the named neural models. "Object-first" uses **oracle masks** for B/C/D, not automatic segmentation. C's discrete search is source-local 0/2 armrests, not arbitrary program synthesis. D's unprojection sees only **visible depth**, never truth backs. Source-colored RGB PNGs are saved for inspection but the fitters do **not** optimize RGB or color semantics. All candidate optimize outputs and candidate render comparisons are computed from the same source ray caster, so internal validity is good but real-camera generalization is untested.

## Primary measured and withheld outcomes

`heldout_global_iou`, `heldout_mean_instance_iou`, `heldout_depth_mae_m`, per-view confusion and depth; exact-known source `center_rmse_m`, `scale_rmse_unitless`, explicit **mixed-unit** param RMSE clearly disallowed as sole score; wall seconds, source-ray-render/objective evaluation counts, process maxRSS and Python/Numpy version. Source camera `K`, world-to-camera and inverse matrices, source parameter truth, starting/error perturbations, exact per-view RGB/label/depth PNGs, and case receipts all stored with SHA source/CI digest. Ground truth appears in the **receipt only**, not in optimizer observation arguments; indirect source-shape template and class types are intentionally known for A/B/D.

Independent **fail/unknown** rules: no secret/test-view parameter choice; no direct source geometry passed into optimizer; unknown self-reconstruction never called *neural/photorealistic* success; A vs B compared only with matched parameter/evaluation budget, B vs D report depth initializer overhead; no rank from one metric or scene; source renders 48×48 and two cases create discretization/camera-scene uncertainty. A, B, C, D, E do not measure model footprint or photorealistic/human avatar accuracy.

## Venue / command

On standard **free public** `ubuntu-24.04` GitHub Actions with Python3, pinned `numpy==2.1.3`, `pillow==11.1.0`, read-only token, 12-minute timeout, 3-day retention, no paid/private Actions, no secrets, no real user images/checkpoints and no scheduled job. Run:

```bash
python3 -m pip install numpy==2.1.3 pillow==11.1.0
python3 research/inverse-scene-r0/bakeoff.py --out out/inverse-scene-r0
```

The code prints `SCENE_SOURCE_SELF_TEST=PASS`, `SCENE_CASE_SUMMARY=` and `INVERSE_SCENE_FINAL=`, and writes complete `receipt.json` plus original source PNG/mask/depth. A green workflow **validates that the measurement and actual optimization executed**, not that segmentation, learned generative models or Oneirifact release are qualified.

## Explicit next independent candidates — gated by actual free resource availability

- **Open3D TSDF CPU (real upstream geometric baseline)** on the same original metric RGB-D/camera outputs; genuine watertight/topology and holdout/sensor depth test. Optional pip/binary download only on runner, no paid cloud. Validate camera/coordinate conventions and depths before comparing.
- **PyTorchGeoNodes (real repo and Blender/PyTorch dependencies)**: first pin source, self-contained native parameter graph, license and installer preflight. Actual differentiable sofa/chair fitting requires Blender Geometry Nodes translation, PyTorch3D and possibly CUDA. A Git checkout or `compileall` alone **cannot** qualify inverse-fitting performance.
- **Mira-Scene / SAM 3D / TRELLIS.2 / GenIA:** pretrained model and checkpoint/rights, NVIDIA GPU/VRAM, data and cloud account/quota gating. This CPU R0 is **not** their benchmark and makes no conclusion about their performance. Do not publish protected Oneirifact source or unrestricted real person footage to public runners.
- Future **reasoning/VLM critic** layer only after actual independent image model with source hashes, blinded view/label negatives, confidence/abstention, and provider data-rights admission; no synthetic rubric score passed off as VLM accuracy. DLE records explicit unknowns.
