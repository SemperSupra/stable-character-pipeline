**Adopt vs bespoke conclusion:** adopt **GStreamer/FFmpeg** for offline/media graph, **PipeWire/OS-native audio** for host routing, **miniaudio/OS-native API** when lightweight device abstraction is required, and evaluate **Faust** for generated DSP/capability surfaces. Keep **SuperCollider/JUCE** as targeted alternatives rather than universal prerequisites. Implement a **small pure typed reducer** for missing policy-free command dedupe and desired/observed lifecycle, not a new media server, broker, scheduler, synthetic CPE taxonomy, repository or DSP engine.

## 3. Separation of concerns

```
UI / CLI / agent --> (local host authorization and tenant/device scope)
                 --> typed command + expected_revision + operation_id
                 --> one pure reducer per session/capability instance
                 --> desired-state receipt + effect intent [NOT effect success]
                 --> qualified adapter: FFmpeg / C# DSP / PipeWire / miniaudio / ASR / spatial
                 --> host observed event (epoch-bound) --> observed-state receipt
                 --> UI / CLI / agent read/status + event projection
```

**The real-time audio processing callback may NEVER call network APIs, lock general state-machine mutexes, allocate unpredictably or persist events.** This common control plane is outside the DSP hot loop; graph reconfiguration should be prepared off-thread and applied at controlled processing boundaries. All OS hardware audio routes, permission prompts, voice-command authorization, storage and sampling clocks remain host-specific.

## 4. Proposed minimal R0 versioned command semantics

The *shared contract*, not necessarily its Go implementation, is reusable across Android/Apple/Windows/Linux/browser/embedded. A reference **Go reducer** is justified by pre-existing Audio Foundry Go sources and synthetic public GHA; native Aural C# should adopt the semantics only after its own conformance/interruption review, not ship a Go runtime solely for API uniformity.

- **Identity**: schema_version, capability ID/version/safety class, session_id, target/device binding, operation_id (scoped to tenant and session), expected revision, *host-proven* authorization/lease, optional monotonic epoch/generation.
- **Commands**: `configure`, `request_start`, `stop`, `close`; **observations, not user commands:** `host_started`, `host_stopped`, `host_completed`, `host_failed`. Human/agent commands cannot forge host events by setting a JSON field.
- **Receipt**: accepted/replayed/conflict/rejected and current snapshot, revision, epoch, pending effect intents, `observed` vs `desired` and linked proof ID. Return the *original* receipt on an identical operation_id retry; reject reused ID with different content. Durable retention/inflight recovery are host adapter responsibilities; a bounded in-memory map alone only proves process-local replay.
- **State**: `new→configured→start_pending→active→stop_pending→stopped`; `active→completed` on real EOS, `*→failed` on error; `terminal→closed`. `stop` from `configured` is terminal without output. `stop` overrides optimistic revision checks and trumps late start acknowledgements. Explicit new session/epoch required before restart.
- **State reconciliation**: effect request success != physical effect observed. `request_start` emits **intent** only; OS adapter must authorize and then emit `host_started` with matching epoch. On STOP-before-start, any later host_started for same/older epoch MUST NOT resurrect active state; reissue/retain stop intent, keep fail-closed device buffer. During crash/restart unknown physical state, recover by querying actual device/OS and conservatively silencing.
- **Concurrency**: one writer/reducer per session, deterministic ordering; expected_revision CAS for state-changing non-STOP commands; independently versioned events and idempotency keys scoped by principal/session. STOP high-priority. Do not assume at-most-once delivery of effect handlers. Streaming frames, clock ticks, speech samples and MIDI note messages are **not** general control-plane events.
- **Capability descriptions**: `list/describe` as typed metadata: audio roles (render/capture/transcribe/speak/spatial/offline), formats, channels, rate, latency class, host-required authorization, safety class, platform constraints, supported version, stop/recovery. A capability declaration is not permission to invoke it.
- **Specialized submachines**: Aural preview and QuietSearch response phases; WineBot recorder state/finalize; spatial DAG render jobs; Voice Foundry synthesis; live mic capture consent; target audio streams. These extend the envelope instead of being flattened into one false set of transitions.

## 5. Primitives to qualify

**Algorithms:** RBJ IIR biquad, time-domain sample rendering, resampling/polyphase interpolation, FFT/PSD/STFT and lufs/EBU R128 where relevant, bounded parameter ramps, PTP/monotonic clock alignment and sample-index timestamp mapping, deterministic seeded RNG, graph topological sort and cycle rejection, DAG immutable plan diff, audio block/zero-copy ring transport.

**Data structures:** typed immutable capability descriptors, command envelope, session aggregate + expected_revision, dedupe map keyed by principal/session/op id + payload digest, append-only *sparse* event receipts (not raw samples), epoch fence token, node/port/link graph, stable device/target IDs, bounded SPSC ring buffer for render/capture, artifact hash/provenance manifest, channel layout / rational sample timebase.

**Formal properties/invariants:**
- STOP dominates delayed/duplicated START and keeps silence until a new authorized session.
- Duplicate command with same id/content -> identical original receipt; same id with different content -> conflict.
- Stale expected revision rejected except STOP; stale epoch hardware acknowledgment cannot resurrect active state.
- No unapproved capture/playback, no bypass of human authorization, no implicit device switching, no cross-target media.
- No audio device effect emitted from a pure read-only API; no untrusted agent/mic transcript invokes privileged host events.
- Callback bounded in time, no unexpected locks/syscalls/allocations; PCM finite, channel/rate/layout and digital bounds validated, no calibration claim.
- Clock and sample order deterministic within declared semantics, reproducible offline outputs and signed/hashed artifact provenance.
- Crash and unknown physical outcome produce **UNKNOWN + fail-closed host-stop**, not fabricated `completed`.

**Test strategy:** table-driven transition matrix and property-based/fuzz commands, STOP/start inversion, dual-UI duplicate IDs, stale epoch, version mismatch, crash-after-accept-before-ACK, authorization and target-confusion, deterministic replay, random adversarial traces, bytes/hashes of original same-op receipt, source extraction/read-only claims; run on $0 public GHA with synthetic data only. Future vertical slice: bind existing Audio Foundry FFmpeg render and Aural C# synthetic render without changing their production control planes.

## 6. Independent work and dependency barrier

1. **First sequential:** agree a public-safe, frozen R0 command vocabulary and effect/observed-state contract; inventory active source/authority first. R0 must be opt-in and cannot override product safety.
2. **Then independent:** A pure Go reducer `audio-control/control/**` and CPU-only CI; B source/prior-art/license/capability research and native platform feasibility `docs/**`; C adversarial test-vector/fixture contract `audio-control/fixtures/**`; D independent existing Aural R10/11 and Stable Character Audio Foundry stabilization in their own branches, no cross-merges.
3. **Sequential acceptance:** compare independent tests, evaluate GStreamer/FFmpeg/PipeWire/Faust/miniaudio instead of expanding bespoke server; integrate one deliberately simple **offline** scene render vertical slice with local GO/NO-GO and no live audio; then (independent after safety authorization) Aural local human-started preview/STOP; only thereafter native device/route/latency/audio calibration. Owner governs merge, signing, deployment/release, remote microphone/network exposure and private identity data.
4. **Stop conditions:** unexpected API side effects, remote microphone/control ingress, identity/medical data leaving private OS, unchanged original GitHub sources being overwritten, tool capability gaps. Preserve existing code and negative evidence; no production acceptance inferred from public runner unit tests.

**Research limitation:** sampled project sources are snapshots on the referenced branches, not an exhaustive code base index. Upstream links were reviewed at retrieval time, not pinned package acquisitions or copied licensed code. The multilingual sweep surfaced few separately verifiable native-language implementations; a second pass may deepen Japanese/Chinese/European-language sources if adoption evidence materially changes.

## 7. Additional concrete source-level anti-duplication findings

- **AgentWebCam** [`agentwebcam/webcam.py`](https://github.com/SemperSupra/AgentWebCam/blob/main/agentwebcam/webcam.py): microphone enumeration uses `sounddevice.query_devices()`, exposes transient numeric device indices, and a worker-thread timeout. `AudioRecorder` starts a `sounddevice.InputStream`, appends copied callback frames to a Python list, and concatenates/writes WAV at stop. Current media mux uses MoviePy. For the shared API **adopt the existing capture backend** and add stable local host device identity, explicit consent/selection, bounded buffer/recording retention, STOP acknowledgement, input-loss/error and output artifact hash; do **not** put a Go/C17 command state machine in the PortAudio callback or falsely equate numeric index with durable target ID.
- **WineBot** [`automation/recorder/__main__.py`](https://github.com/SemperSupra/WineBot/blob/main/automation/recorder/__main__.py) + [`api/routers/recording.py`](https://github.com/SemperSupra/WineBot/blob/main/api/routers/recording.py): carries `recorder.state`, `ffmpeg.pid`, segment manifest/timeline ID, recording pause/resume and separate finalization state; API has an `operation_id` and returns `already_recording`/accepted-like receipts. A generic reducer must not replace FFmpeg segment/PID state or mark completion merely on command accept. **Use target/session operation key and poll actual mux artifact / process termination**; crash-and-restart replay needs a durable host-owned operation registry, not R0's 512-entry in-memory map.
- **Spatial Audio** [`spatial-contract/contract/scene.go` @ PR #22](https://github.com/SemperSupra/stable-character-pipeline/pull/22): explicit ENU coordinate convention, strict monotonically increasing keyframe timestamps, channel/LFE profile order, no double-applied HRTF, and original source digest. These are **domain validator invariants** that precede any common `request_start` state transition; the generic control envelope should reference their validated plan digest, not reinterpret their geometry or source rights.
- **Audio Foundry** [`audio-foundry/scene/scene.go` @ PR #11](https://github.com/SemperSupra/stable-character-pipeline/pull/11): existing bounded manifest `Plan()` verifies SHA-256 file custody and refuses escaping symlinks; `Render()` uses temporary file / no-overwrite semantics and FFmpeg, plus audio-level QC. This is an existing *admission boundary* worth adapting, not rebuilding. Important difference: a deterministic offline render may be retried against **content-addressed identical inputs and output target**; real device playback cannot be deduplicated by a file hash alone.

R0 Go command-reducer proof and portable schema remain deliberately **separate** from each of these existing process adapters. Acceptance requires the owning projects' source/CI/hardware gates, not just a common word for STOP.
