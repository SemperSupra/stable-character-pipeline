# R009 — Original adult body and detachable wardrobe (research)

**Status:** Source-original, two fictional adult characters, reversible scene/asset layer. Structural and native visual quality are independently gated. Not photorealistic, anatomically accepted, physically simulated, or release-approved. Do not confuse unclothed mesh with a high-fidelity body scan.

## Separation contract

Each character has an anatomically neutral full-body base **beneath** garments. It is not generated by hiding the jacket/trouser material without providing torso, arms, legs, pelvis, and bare feet. The base body is skinned to exactly the same 35-joint skeleton as the clothing. No explicit genital geometry. Skin/body and hair persist in every outfit. Individual GLB nodes are:

| Slot | Semantic purpose | Present in unclothed | Present in signature | Present in alternate |
|---|---|---|---|---|
| `body` | skinned adult body, head, arms, hands, pelvis, legs, feet | yes | yes | yes |
| `hair` | detachable groom geometry | yes | yes | yes |
| `top` | original coral/teal jacket and sleeves | no | yes | no |
| `bottom` | original trousers | no | yes | no |
| `footwear` | original skinned shoes | no | yes | yes |
| `accessory` | Aster scarf | no | yes, where available | no |
| `alt_top` | independently selectable recolored jacket mesh slot | no | no | yes |
| `alt_bottom` | independently selectable recolored trouser mesh slot | no | no | yes |

The initial alternate is a *different material/colorway of the same garment cut*, not a redesigned jacket or trousers. Each clothing slot is a **distinct glTF mesh node with the same actor skin index**, not just a shader/material variant on the combined body. The GLB can be loaded by Blender and inspected as a complete rigged character; the external JSON manifests node/mesh/skin indices and deterministic whole-asset hashes.

## Reproduction with already admitted source

From the project directory `qualification/original_reusable_characters`:

```sh
python3 -m unittest -v test_original_glb test_humanization_v2 test_rig35_v2 test_phase_gait35 test_modular_wardrobe_v1
python3 modular_wardrobe_v1.py --out /tmp/r009-wardrobe.glb --manifest /tmp/r009-wardrobe-manifest.json
```

Use the existing pinned native Blender 4.5.15 source pipeline for the editable `original_park_editable.blend`, actual front/oblique H.264, and 6 preset still images. In an authorized Blender environment, create immutable new editable variants using:

```sh
blender -b original_park_editable.blend --python-exit-code 8 \
  --python wardrobe_switch_blender.py \
  -- --preset unclothed --out body_only.blend --receipt body_only.json

blender -b original_park_editable.blend --python-exit-code 8 \
  --python wardrobe_switch_blender.py \
  -- --preset alternate --out alternate_outfit.blend --receipt alternate_outfit.json
```

Valid preset names: `unclothed`, `signature`, `alternate`. Optional `--actor AsterOriginal` or `--actor JuniperOriginal` modifies one character and leaves the other unchanged. Writes refuse the input .blend path. Garments are turned off via Blender render/viewport visibility and **never deleted**; reopen the source .blend or apply another preset to reverse a change. The JSON receipts preserve source and derived SHA-256.

## Portable GLB variants (for ordinary glTF viewers)

The full master wardrobe GLB is an **authoring container** with all garment nodes reachable. Most generic glTF viewers cannot toggle per-node visibility; they will display original and alternate outfits at the same time if opened directly. Use the portable export command to choose which garment nodes are active in the scene graph:

```sh
python3 wardrobe_export_preset.py --input wardrobe.glb --manifest wardrobe.json \
  --out unclothed.glb --receipt unclothed.json --aster unclothed --juniper unclothed

python3 wardrobe_export_preset.py --input wardrobe.glb --manifest wardrobe.json \
  --out dressed.glb --receipt dressed.json --aster signature --juniper signature

python3 wardrobe_export_preset.py --input wardrobe.glb --manifest wardrobe.json \
  --out mixed.glb --receipt mixed.json --aster signature --juniper alternate
```

This is a reversible clone of the GLB's root scene graph, **not a body deletion or destructive sculpt**. It retains every source geometry, material, skin and animation accessor inside the binary for traceability, but viewers traverse only the selected body/groom/garment nodes. A portable file is usually larger than a fully compacted export; compacting orphan meshes is deferred until source and visual qualification. The two actors can wear different presets in the same scene.

## Adding genuinely different future clothing

Use a separate garment source `<actor>-<garment-id>.glb`, not a destructive resculpt of the body. Author the jacket, skirt, shirt, trousers, shoes, accessories or other apparel in the identical actor rest pose and units. Bind the garment to the corresponding 35-joint skeleton, with validated glTF joint indices, normalized weights and correct sign conventions, and register a unique wardrobe slot/model identifier and asset hash in the manifest. Validate all-frame skin deformation, clipping, collision, motion fit and source-by-operation rights *before* marking the new garment compatible. A material swap alone does not establish those physical tests; changing clothing color and changing garment topology are separate operations.

Current v1 supports native preset switching and separate geometry slots; it does **not** yet have a generic third-party garment-import command. Adding external garment meshes remains a gated follow-on workcell. Original self-authored geometry and materials are reusable subject to owner's selected publication license; do not infer training/redistribution grants for future external clothes.

## Three audiences

- **Human UI/UX:** original editable .blend objects are named `<actor>_Wardrobe_<slot>`, so visibility and material can be changed in Blender's Outliner/Material tabs; six representative previews support visual comparison.
- **Automation:** deterministic Python builder + JSON manifest + Blender CLI preset switching. Nonzero test/build results block promotion.
- **Agent/DX:** JSON source/preset/skin references, separate machine-readable scene receipts, SHA lineage and explicit `UNKNOWN` anatomical/cloth QA keep the same API contract legible to automated evaluators.
