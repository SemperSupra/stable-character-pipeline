# R060 — Real Cycles per-frame depth and segmentation consistency under controlled motion

Authority: private [R037 DOE #176](https://github.com/SemperSupra/stable-character-pipeline-private/issues/176), [R009 MVP #23](https://github.com/SemperSupra/stable-character-pipeline-private/issues/23) and visual critic #168. Parent: public [R057 #576](https://github.com/SemperSupra/stable-character-pipeline/pull/576) exact head `a2d4e4fb0c02895569dcf556541d8d65e254339c`. Isolated files `temporalprobe/` and independent public CI only.

**Question:** Does actual decoded perspective Cycles EXR depth/index remain source-faithful when scene geometry changes across three source-known frames and camera remains exactly fixed? This is **not** skinning, a rigged human, photoreal animation or learned motion. It is the original 13-object stylized head proxy group translated in X by fixed offsets frame 0 = 0, frame 1 = +0.36 and frame 2 = -0.28 uncalibrated scene units, from one Blender in-memory scene; neck/torso/ground remain fixed. 65mm perspective, original static procedural base, real per-frame Cycles PNG + multilayer EXR, actual source mesh digest and world matrix pose digest recorded separately per frame.

**Predeclared gates:** exact 0/1/2 frames and fixed offsets; all 3 pose + geometry SHA digests distinct; one unchanged perspective camera SHA; at least 64 stable source `scene.ray_cast` points per frame; independent official OpenEXR decoded *camera-axis depth* `-camera_local_hit.z`, not Euclidean ray length, and object index meet original R057 thresholds (>=98% joint matches, <=0.05 source-unit depth, <=0.01 object ID); frame-0 to frame-1 and frame-0 to frame-2 genuine RGB change >=1% of pixels at >2/255. All original PNG/EXR/source bytes SHA-bound. Malicious fixtures change frame order, offsets, geometry/pose digests, camera, depth, rights, object index and nonfinite values; all fail closed. This does not assume temporal optical-flow vectors are physically correct.

**Reproduce:** `.github/workflows/r060-temporal-pose.yml`. Disposable **free public Ubuntu** CPU `blender -b -t 2 --python temporalprobe/scene.py -- --out out` followed by pinned venv OpenEXR+NumPy `python -m unittest discover -s temporalprobe -p test_audit.py -v` and `python temporalprobe/audit.py --root out --out out/r060_report.json`. No private Actions minutes, protected models/persons, downloaded donor weights or server.

**Acceptance limit:** `PASS_NARROW_REAL_MOVING_MESH_DEPTH_BY_FRAME` means exactly three independently source-checked **rigid multi-mesh head positions** with actual decoded EXR depth+object consistency and visually different frames. It does **not** certify skin deformation, joint/bone retargeting, native MakeHuman rig, stance/slip/penetration, motion translation models, anatomy coupling, shading normals, temporal physically consistent motion or source-admitted Naomi/Alison cinematic H.264. Those remain separately held by private product/R009 gates.
