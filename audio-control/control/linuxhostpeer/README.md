# Audio Control R3 — Linux SO_PEERCRED host-origin donor

**Linux-only, source-isolated, nonproduction peer-credential interview**. This package reuses Linux `AF_UNIX`, `SO_PEERCRED` and POSIX socket permissions instead of accepting `host_started/host_stopped` assertions from a generic JSON caller. It is an upstream **OS primitive**, not a new identity provider, general cross-platform API or real audio server. The existing R0 reducer is unchanged.

A real subprocess (the Go test binary launched as a distinct child) connects to a private Unix socket and sends a JSON claim falsely asserting `host_authorized=true` with a forged PID. The parent reads **kernel-populated** `SO_PEERCRED` and matches an out-of-band expected host process PID and UID. False PID and UID bindings are rejected even when the JSON has an apparently valid host event. An existing socket path is refused without overwrite, and the socket filesystem mode is restricted to 0600.

**What is not proven:** treating the same UID as inherently trusted would be insufficient; the test binds exact PID but a production system must protect PID reuse, process spawn/exec lifecycle, user-session binding, Linux namespace translation, permissions on socket ancestors, sandbox or container boundaries and TOCTOU. If the trusted process is compromised, SO_PEERCRED does not make its **content** truthful. This primitive does not attest an audio device, speaker route, headset, actual STOP, quiet-search observation or acoustic level. It is Linux-specific; Windows named-pipe token impersonation and macOS peer credentials require their own native interface and testing. **Do not expose it as an untrusted user/agent-accessible host-event RPC.**

Run `cd audio-control/control && go test -race -count=1 -v ./linuxhostpeer && go vet ./linuxhostpeer`. Public Ubuntu-only CI is intentional; all media inputs are synthetic and no device is opened. This is an adoption candidate, not an authorization to capture/play recordings or merge to production.
