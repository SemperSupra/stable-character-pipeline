# Audio Control R2 — SQLite WAL transactional-outbox interview

**Synthetic CPU-only prior-art probe, NOT a new production implementation.** This bounded Python 3.12 stdlib `sqlite3` workcell qualifies SQLite's well-established local transaction/WAL primitives as a possible durable host adapter for the existing [Audio Foundry issue #9](https://github.com/SemperSupra/stable-character-pipeline/issues/9). It does not propose Python for an audio DSP callback or rewrite the existing Go/C# products. No external package, internet service, device, microphone, private voice, or personal health data.

The atomically committed unit is an **accepted operation receipt plus outbox effect intent**, keyed by `(principal,session,operation_id)` with immutable command digest. Two writers racing to admit the same START may produce **only one new synthetic effect intent**; repeat admission returns the original receipt with no re-dispatch. STOP fences a pending START and creates a stop intent within a SQLite `BEGIN IMMEDIATE` transaction. A previously unknown device remains `unknown_stop_requested`, never a fabricated `stopped` observation. Process restart is tested by a new Python process reading the on-disk database; recovery reports `requires_host_reconcile=true` and `may_issue_start=false` regardless of persisted state.

**Hard limitations:** the `synthetic_human_grant` boolean is a test fixture, **not authentication**. The outbox is not connected to real hardware, lease validation, an authorized device supervisor, a receipt signature, process-failure exactly-once delivery, or actual STOP acknowledgement. A pending START row visible on restart must **not** be dispatched automatically. SQLite `PRAGMA synchronous=FULL` and WAL mode are exercised but not an independent proof of power-loss tolerance, filesystem fsync, multi-host distributed coordination, or atomic external side effects. Real-world safety needs an independent OS-sourced human grant, verified host/device/epoch, crash-fault injection, stopped-observation witness, durable cleanup, and owner approval. The Python oracle is for comparison; if later admitted, choose a supported SQLite adapter in the owning runtime rather than embedding another Python server.

Reproduce: `cd audio-control/experiments/sqlite-outbox && python -m unittest discover -p 'test_*.py' -v`. Public three-OS GitHub Actions test all branches only with constructed original synthetic metadata. Draft/unmerged; do not port this directly to medical playback or user recording.
