# R4 macOS kernel-origin host observation donor

**Nonproduction, device-free Darwin-specific source witness.** Native C11 process test creates a private AF_UNIX socket, forks a real subprocess, and receives a deliberately forged JSON payload `{"host_authorized":true,"pid":987654321,"uid":0}`. The server retrieves the **actual peer UID/GID from `getpeereid`**, and the actual child PID through `getsockopt(SOL_LOCAL, LOCAL_PEERPID)`; none of those facts derives from the JSON payload. The socket and parent directory permissions are restricted and cleaned up. It runs with Apple clang on a public macOS GitHub-hosted runner and opens no audio device.

**Limits:** this is only a host-peer observation primitive. Matching a PID/UID is **not** OS authorization to play sound, a consent signal, proof of device silence, protected per-user session isolation, protection against PID reuse, sandbox escape or compromised same-UID processes. The accepted host's actual process spawn provenance, lease, executable signer, security framework entitlements, lifecycle and per-device route still require host-owned checks. No complete mTLS, network service, Go/C# runtime embedding, medical/sound claims or production artifact is built.

This is a **separate macOS evidence lane**, not an edit to Linux `SO_PEERCRED` [PR #752](https://github.com/SemperSupra/stable-character-pipeline/pull/752) or local actor host STOP [#738](https://github.com/SemperSupra/stable-character-pipeline/pull/738). The cross-platform common core should expose a **host-verified capability event** but retain OS-specific implementations behind the adapter. Exact compiler and test are in `.github/workflows/audio-control-r4-macos-peercred.yml`. Keep draft/unmerged; no production or physical playback authority.
