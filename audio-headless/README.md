# Headless open audio-authoring primitives — test-only

This isolated qualification implements an actual cloud execution test of two *human-facing* music tools, rather than assuming their GUI functionality is accessible from an agent. Authority: [Spatial/Audio Foundry issue #18](https://github.com/SemperSupra/stable-character-pipeline/issues/18) and parent [Audio Foundry #9](https://github.com/SemperSupra/stable-character-pipeline/issues/9).

**LMMS:** the pinned [source code](https://github.com/LMMS/lmms/blob/bed447baab187ea6292449048e0b1aab16082e3b/src/core/main.cpp) expressly defines CLI `render` and `rendertracks` in its core-only pathway, with directory `--output`, file `--format wav` and `--samplerate`. CI installs the distribution binary and downloads the official tutorial `data/projects/tutorials/editing_note_volumes.mmp` from the exact pinned upstream source revision, without adding it to our repo. CI invokes real `rendertracks` unattended on a public CPU runner and checks waveform format, duration, decode, non-silence and SHA. The package's installed version will be recorded in workflow logs; the upstream source lookup alone does NOT prove the distribution package has identical behavior.

**MuseScore:** CLI `musescore3 -o score.mid input.mxl` via headless/offscreen X server is tested against the exact CC0 transcription **Clara Schumann, Sechs Lieder, Op.13 No.1, Ich stand in dunklen Träumen** from [OpenScore Lieder](https://github.com/OpenScore/Lieder/tree/38c5db510224d9facdc4b08d741fc788cfb58ea8/scores/Schumann,_Clara/6_Lieder,_Op.13/1_Ich_stand_in_dunklen_Tr%C3%A4umen). The score transcription corpus has a CC0 LICENSE.txt; no third-party performances/recordings are included, and the pinned compressed MusicXML is fetched transiently. CI structurally validates any generated Standard MIDI file and notes the original source/target hashes. This is **conversion**, not yet semantic round-trip of all lyrics, articulation or score instruments through our restricted Go music contract.

Both tools have public free-source code but differing licenses/dependencies; this test does not build or redistribute them, upload the rendered sound, or merge/deploy a production tool. Actual samples are temporary and removed after runs. Python is used only as ephemeral test glue for FFprobe/MIDI inspection, not a new production service; Go remains the preferred orchestration layer.

**Expected next gates:** exact tool versions from CI, independent playback QC, LMMS source project parameter edit and re-render with altered musical notes, MuseScore MusicXML edit round-trip, import fidelity and explicit lossiness report, and UI/source/API equivalence. Real Ardour session creation and reimport remains separate issue #16. This branch cannot resolve iPhone user playback or claim Dolby/THX spatial sound.
