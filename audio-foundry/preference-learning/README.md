## Purpose
Capture the human's **intent, reference examples, positive/negative demonstrations, hard constraints, and subsequent choices** independently of the mechanism used to produce a sound. No operator should have to know terms such as pitch, timbre, breathiness, formant, intonation or vibrato. For each attribute, provide a short explanation in EN/DE/TH, two or more **actual generated and source-hash-pinned WAVs**, user-adjustable examples, a blind comparison, optional free-text reasons and a "can't tell"/"neither" option. Every changed parameter must show which physical/acoustic dimension was intended to change; don't describe any synthetic educational vowel as intelligible speech or validated biology.

## Minimal contracts
- `contracts/intent.v0.schema.json`: a revisioned, source-neutral human design target. References are only hashes plus rights receipts; never embed recordings. Distinguish target character **identity**, transient vocal/physical state, and stylistic delivery in an eventual private extension.
- `contracts/critic-receipt.v0.schema.json`: one independent critic's task, algorithm/checkpoint version, applicable result or abstention, observed metrics with units, uncertainty, original evidence and resource cost. Human preference doesn't override physical, licensing, identity or scientific hard gates.
- `contracts/preference-event.v0.schema.json`: append-only human choice with randomized shown positions and content hashes, plus reason codes/explanation, language, optional consent and playback context. Every user choice is data, not an automatic permission to retrain, release, publish or copy protected voice assets.

These are **early wire contracts**, not a complete runtime privacy policy. Runtime must reject private events on public runners, detect invalid source classification, enforce consent and maintain lineage. The `$id` uses example.invalid to avoid implying an authorized production endpoint.

## Audience parity
- **Human creator / reviewer**: progressive disclosure, exemplar listening, natural language/voice guidance when admitted, lay explanations, referent comparisons, undo and target policy history; controls never require technical jargon.
- **Human using assistive technology**: keyboard/screen-reader semantics, labeled native audio playback, transcripts or descriptive alternatives, no autoplay, large targets, high contrast, multilingual EN/DE/TH, non-audio way to contribute intent, randomized tests with no information leakage. Native iPhone VoiceOver/device acceptance remains UNVERIFIED until HIL.
- **Automation**: same typed input/receipt JSON, deterministic candidate IDs, source hashes, budget/timeout contracts, no privileged access, fail-closed event/custody gates and idempotent replay.
- **Agent / developer / operator**: inspectable `Generate→Critic→Judge→Optimizer→Replay` calls, discoverable capabilities, evidence links, metric disagreement, confidence/abstain, bounded PR proposal, explicit release gate and operational health/telemetry.

## Research donor/algorithm bake-off (NOT selections)
1. **Listening-test UX**: our source-neutral native HTML/Go vs Gradio vs webMUSHRA *experiment patterns only*. Review webMUSHRA proprietary license before source reuse. Test randomized AB, neutral volume, learning panels, ties, neither, inability to judge, actual audio controls, keyboard + screen-reader and iPhone. Prefer no Python service dependency for deployment.
2. **DSP critics**: Go/FFmpeg native meters vs Praat/Parselmouth and VERSA small CPU metrics; deliberate silence/clips/clock/impulse errors, isolated vs source-coupled resonance, pitch/octave errors, timbre shifts, breath confounds, sampled clocks. Qualify metric accuracy, failure/abstain and wall CPU on exact files; do not equate spectral centroid with human "warmth".
3. **Perceptual critics**: CLAP prompt-audio comparison, Whisper multilingual ASR (EN/DE/TH), Audiobox Aesthetics independent axes, and VERSA selected metrics. Freeze model/weight SHA, license, reference correctness, compute ceiling; include novel sounds, real synthetic negatives, domain-shift abstentions. Compare agreement with **withheld** human judgments; no private person refs on free cloud.
4. **Optimizers**: random/LHS/Sobol vs local sensitivity, Nelder-Mead/CMA-ES, Optuna TPE and Nevergrad ask/tell; identical generation budgets, fixed seed ensembles, frozen target and independent critics; compare regret, Pareto coverage, total CPU/GPU time, reproducibility, stability and sensitivity to reward hacking. Start with lightweight Go optimizer; Python experiments run as disposable research adapters only.
5. **Preference models**: zero-memory baseline, per-attribute explicit sliders, Bradley–Terry pairwise logistic ranking, ties/annotator noise model, and active-query model (uncertainty/disagreement/diversity). Compare withheld pairwise prediction, human review counts and undo correctness. Store raw choices separately from learned predictions; calibrate per task/language instead of a global scalar.

## Staged rollout and maintained execution

B. **Bounded cloud $0**: admitted standard **public** GHA jobs for synthetic-only CPU, ephemeral workers, capped runtime and no private secrets. Optional OCI Always Free for stateless coordinator only with access/auth/cost gates; no assumption resource exists. Store original source/receipts/DoE decisions in Git + DLE, large approved media in restricted Drive with exact readback; no duplicate binary history.
C. **Adaptive experiment**: 3 mechanisms × controlled DoE candidate batches, independent critics, multiobjective Pareto constraints, human A/B active queries. Keep baseline, adaptive and regression fixture hashes; shared scene `scene_audio.v1` remains separate owner.
D. **Model adapter bake-offs**: optional Kaggle/Colab GPU interactive experiments for **public, synthetic, rights-approved** inputs, never unattended guaranteed jobs; heavy/private characterization uses authorized sovereign local actor. Do not build a critical path relying on free GPU availability.
E. **Deploy**: signed/pinned slim **Go** service container (one versioned image across GHA/OCI/TrueNAS after approvals), disposable runtime + optional application layer + persistent encrypted data/config separate; deny unauthenticated public use and avoid placing protected references on public deployments. No actual deploy authorized by this draft.
F. **Operate and maintain**: versioned policy and reproducible cost budgets; SHA receipts, OpenTelemetry-compatible event logs (no raw voice), failure taxonomy, quality drift, adversarial holdouts, software/dependency/rights reviews, feedback appeals/undo, promotion/rollback. Auditors can reconstruct any decision from immutable source and experiment records. Human owner acceptance for semantic/model identity changes, mergers/releases/deploys.
